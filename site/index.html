System overview

Members Only is a local Python boundary in which an AI agent can propose work, but the member remains the authority for sensitive actions. The system checks the proposal before execution, requires approval where needed, and records a safe result without copying the private payload into the trace.

Agent proposal→

Structured action, arguments, destination, and member context

Sensitivity inspector→

Credential, personal, private-message, and destination findings

Policy gate→

Allow, requires approval, or deny

Member approval→

Decision bound to the exact proposal digest

Capability manager→

Short-lived, one-use permission for the approved proposal

Local adapter→

Synthetic note and message actions, with external destinations rejected

Trace and receipt→

Safe evidence of the decision and execution outcome

The MVP is local and synthetic. It has no request-time network dependency and does not connect to Web MCP or external services.

Authoritative proposal flow

01

Intent An agent submits a typed proposal naming the action, arguments, and destination.

02

Inspection The sensitivity layer returns finding types and locations without echoing secret values.

03

Decision Policy maps the findings and destination to allow, requires approval, or deny.

04

Approval The member approves the exact proposal. The approval stores a stable SHA-256 proposal digest.

05

Authorization A capability is issued and consumed immediately before the local adapter runs.

06

Receipt The result is recorded as a safe trace and receipt. A replay is denied.

Design invariantAgent text, UI state, or a copied capability never substitutes for policy and member authority.

Sandbox security shield

The shield sits outside the application workflow. It makes the local MVP default-deny and requires both machine verification and explicit approval before a request reaches a broker.

Machine check→

Verify trusted workload, hardware identity, and a signature bound to the exact request.

Approval check→

Accept an exact member capability or an exact pre-approved rule. Unknown requests stop.

Broker route→

Forward only through the configured broker for the request channel and destination.

Default deny→

Unconfigured ingress, egress, updates, telemetry, model, and log routes are refused and recorded.

SeamPython provides the control-plane interface. A later adapter can replace static verification with TPM, enclave, or orchestrator-backed attestation.

Traces and receipts

The demo emits a trace for each important state change and creates a receipt for the final outcome. The record is designed to answer, “What happened?” without becoming a second copy of the sensitive content.

Trace

State transition, actor-safe identifiers, finding types, and decision reason.

Receipt

Action identity, execution result, and a bounded failure reason.

Omitted

Raw credentials, private message bodies, and payload-like detail.

Current boundaries

  • Local synthetic actions are implemented. Real external messages, payments, and account changes are not.
  • Web MCP is intentionally excluded from this project scope.
  • Detectors are signals. They cannot guarantee that every sensitive value is found.
  • The member remains responsible for approving high-impact actions.
  • The current shield is a software control plane. It does not claim OS-level network containment or hardware attestation yet.
  • This documentation describes implementation evidence, not user adoption or commercial scale.
